\section{Errors}
Errors can be confusing in lattice cryptography; this section seeks to demystify them. 

\subsection{RLWE Security}
First, the ``lattice'' in lattice cryptography is based on the \emph{canonical embedding} of a ring element. Let $t(X)$ be a polynomial / ring element. The canonical embedding of $t(X)\in R$ is
\[\sigma(t(X)) = \set*{t\parens*{\exp\parens*{2\pi i\cdot (2j+1)/m}}}_{0\le j<N}\in \C^N.\]
The lattice is then $\Lambda=\sigma(R)$. We know a nearly-orthogonal basis for this lattice, so we can solve the closest-vector problem (CVP) on it quite easily. In fact, we do exactly that in the CKKS encoding procedure: we are given a vector in $v\in \R^N$, then round off the coefficients to get a ring element $r\in R$. But $\sigma(r)$ is the closest lattice point to $v$ in $\Lambda$.

An RLWE instance is a pair $(a, b=a\cdot s+e)$. The security of RLWE essentially depends on the hardness of CVP in the sublattice $\Lambda_a$ of $\Lambda$ induced by $a$. In short, the goal of the RLWE problem is to recover $s$. The best way to do this appears to be to find the closest lattice point to $\sigma(b)$ in $\Lambda_a$, which corresponds to $\sigma(a\cdot s)$. Given $a$, we can then recover $s$ by inverting a linear operation inducing multiplication by $\sigma(a)$.

There are good algorithms for solving CVP when the error term has a very small $\ell_2$ norm. For security, the norm needs to be close to (or larger than) the minimum distance of $\Lambda_a$. The exact details go beyond the scope of this document; the takeaways are that
\begin{itemize}
    \item The $\ell_2$ norm of (the canonical embedding of) the RLWE error term matters for security.
    \item It must be at least a certain size, or CVP becomes easy.
\end{itemize}

Theoretically speaking, there is also an upper bound on the size of the error, though this doesn't manifest directly in encryption schemes. The short version is that encryption schemes are based on the hardness of solving CVP, and if the error term grows so large that the nearest lattice point is \emph{not} $\sigma(a\cdot s)$, then the reduction breaks.

\subsection{FHE correctness}
While having an error terms is crucial to the security of RLWE, it also introduces problems in homomorphic encryption schemes because if the error grows too large, it may overwhelm the ``signal'' of the message. This is less of a problem for CKKS than for other FHE schemes, but it still matters. In particular, we need $\length{\sigma(e)}_\infty\ll \Delta$.\footnote{Note that since $\Delta < q$, this implicitly avoids wraparound mod $q$.} This is because we decryption recovers $\Delta\cdot m + e$, so we divide by $\Delta$, making the error term negligible.


\subsection{Connection between these notions of size}

$\length{\sigma(e)}_2 = \sqrt{n}\cdot\length{e}_2$, where $\length{e}_2$ is the $\ell_2$ norm of the coefficients of $e$. This induces a bound on the infinity norm:
\[\length{\sigma(e)}_\infty\le \sqrt{n}\cdot \length{e}_\infty.\]

However, the precise value we care about for precision is $\length{\sigma(e)}_\infty$. The maximum error (in each slot) is therefore $\frac{\length{\sigma(e)}_\infty}{\Delta}$.

A rough estimate of the number of bits of precision is $-\log_2\parens*{\frac{\length{\sigma(e)}_\infty}{\Delta}}$. This assumes that the message has (scaled) magnitude $\approx 1$ in each slot.

\section{NTT}
\subsection{Multiplication in Modular Polynomial Rings}
Let $S=T[X]/(U(X))]$ be a generic modular polynomial ring. Elements of $S$ are polynomials in $X$ with coefficients in $T$, and with degree $<\deg(U)$. Let $a,b\in S$. We can compute $a\cdot b$ using standard polynomial multiplication, followed by reduction by $U(X)$. Let $U(X)=\sum_{i=0}^N u_i\cdot X^i$. The definition of ``modding'' by $U(X)$ is that we set $U(X)=0$. Therefore in the reduction phase, we replace all occurrences of $X^N$ with $\sum_{i=0}^{N-1}-u_i\cdot X^i$ (we simply moved all of the lower-degree terms to the left-hand side). 

While the algebraic view is functionally adequate, we can get additional insight by viewing modular polynomial multiplication as a linear algebra problem. We can write this as follows:
\begin{align}
	a(X)\cdot b(X) &= a(X)\cdot \parens*{\sum_{j=0}^{N-1} b_j\cdot X^j} \bmod U(X) \\
	&= \parens*{\sum_{j=0}^{N-1} b_j\cdot \parens*{a(X)\cdot X^j}} \bmod U(X) \\
	&= \parens*{\sum_{j=0}^{N-1} b_j\cdot \parens*{a(X)\cdot X^j  \bmod U(X)}},
\end{align}
where the last line follows because $b_j$ is a constant and doesn't require modular reduction. We have just written out a matrix-vector multiplication of the form $C_a\cdot b$, where the $j\th$ column of $C_a$ is the coefficient vector of $a(X)\cdot X^j  \bmod U(X)$ and $b$ is the coefficient vector of $b(X)$. When $U(X)$ has distinct polynomial roots in $T$ (which will always be the case for rings used in FHE), then we can \emph{diagonalize} $C_a$. That means there exists a matrix $F$ such that $F^{-1}\cdot C_a\cdot F$ is a diagonal matrix. Under these conditions, the convolution theorem applies so
\[a\cdot b = F((F^{-1}\cdot a)\odot (F^{-1}\cdot b))\]
The matrix $F$ has columns corresponding to \emph{eigenvectors} of $C_a$. 

\subsection{DFT Decompositions}
In this section, let $m=p^e$. Given an $m\th$ root of unity $\omega_m$ for an arbitrary $m\in\Z$, $\mathsf{DFT}_m$ is the $m\times m$ linear operator defined as $\bracks{\omega_m^{ij}}$. In other words, it evaluates the [polynomial] coefficient vector at \emph{all} $m$ $m\th$ roots of unity, $\set{\omega_m^i}_{i\in\Z_m}$. Applying a generic $m\times m$ linear transformation requires $m^3$ operations, but we can apply the $\mathsf{DFT}_m$ matrix with only $m\log(m)$ operations using a clever decomposition technique due to Cooley-Tukey and/or Gentleman/Sands~\cite{cryptoeprint:2024/585}. There are many ways to decompose DFT into smaller pieces; we give two here.

The \emph{decimation-in-frequency} (DIF) decomposition is
\[\mathsf{DFT}_m = (I_2\otimes \mathsf{DFT}_{m/2})\cdot T_m\cdot (\mathsf{DFT}_2\otimes I_{m/2}),\]
where
\[\mathsf{DFT}_2=
\begin{bmatrix}
	1 & 1 \\
	1 & -1
\end{bmatrix}
\]
and
$T_m$ is the $m\times m$ diagonal matrix with $\omega_m^i$ in the $i\th$ diagonal entry. This is the decomposition given in~\cite{cryptoeprint:2013/293}.

An alternate decomposition is known as \emph{decimation-in-time} (DIT):
\[\mathsf{DFT}_m = (\mathsf{DFT}_2\otimes I_{m/2})\cdot T_m\cdot (I_2\otimes \mathsf{DFT}_{m/2}).\]
\enote{I think the twiddles are the same for DIT, but I'm not 100\% sure...}

\cite[C.2.5]{cryptoeprint:2015/1134} describes additional variations on this decomposition. 

As written, the DIF decomposition yields the output in \emph{bit-reversed} order compared to the matrix definition of DFT. In more detail, this means that the DFT evaluates the [polynomial] coefficient vector at  $\set{\omega_m^{\mathrm{BR}(i)}}_{i\in\Z_m}$. As an example, the ``standard'' $\mathsf{DFT}_4$ would output the evaluations of a polynomial $p(X)$ as $[p(\omega_4^0), p(\omega_4^1), p(\omega_4^2), p(\omega_4^3)]$. When using DIF, the default order is instead bit-reversed: $[p(\omega_4^0), p(\omega_4^2), p(\omega_4^1), p(\omega_4^3)]$. This can of course be ``tweaked'' to the standard ordering, but we will see that this is unnecessary.

The inverse DIF decomposition is
\[\mathsf{DFT}_m^{-1} = (\mathsf{DFT}_2^{-1}\otimes I_{m/2})\cdot T_m^{-1}\cdot(I_2\otimes \mathsf{DFT}_{m/2}^{-1})\]
and this expects its \emph{inputs} in bit-reversed order, but outputs the standard order.
As an optimization, note that $\mathsf{DFT}_2^{-1}=\frac{1}{2}\mathsf{DFT}_2$, so we can replace $\mathsf{DFT}_2^{-1}$ with $\mathsf{DFT}_2$ and apply a final division by $m$.

\subsection{Multiplication in $\Z[X]/(X^N+1)$}
%	\cite{Harvey_2014} talks about using $[0,2q)$ for efficiency in FFTs.
FHE typically operates over the $m\th$ cyclotomic [polynomial] ring $R=\Z[X]/(\Phi_m(X))$, where $\Phi_m(X)$ is the $m\th$ cyclotomic polynomial. As an example, when $p=2$, we let $N=m/2$. The $m\th$ cyclotomic polynomial is $X^N+1$. 

We can multiply two polynomials in this ring using textbook polynomial multiplication. In the $p=2$ case, this amounts to replacing occurrences of $X^N$ with $-1$. This requires $\mathcal{O}(\phi(m)^2)$ operations. As noted above, we can do this much faster by using the convolution theorem. In the standard power-of-two cyclotomic ring, the connection to the convolution theorem is that we define $F^{-1}$ as the matrix whose \emph{rows} are the eigenvectors. This is apparently an equally valid way to look at the relationship between $F$ and $F^{-1}$, though we note it yields different operators than if we instead make $F$ have eigenvector columns.

Under this definition of $F$ and $F^{-1}$, the $i\th$ row of the forward transformation $F^{-1}$ is $\set{\omega_m^{(2i+1)j}}_{j\in[0,N)}$, i.e., it corresponds to evaluation at $\omega_m^{(2i+1)}$. This can be viewed as a tweak to DFT, and therefore enjoys a similar decomposition to DFT. Specifically, $\mathsf{DFT}_{m/2}$ evaluates its input at $\omega_{m/2}^i=\omega_m^{2i}$ for $i\in[0,{m/2})$. Therefore, we just need to shift the evaluation from $\omega_{m/2}^i=\omega_m^{2i}$ to $\omega_m^{2i+1}$, which we can do my pre-multiplying by a diagonal matrix $\hat{T}_m$, which is the $\frac{m}{2}\times\frac{m}{2}$ diagonal matrix with $\omega_m^i$ in the $i\th$ diagonal entry. Another way to look at this is that the diagonal matrix $\hat{T}_m$ shifts the \emph{columns} of $\mathsf{DFT}_{m/2}$. Recall that the $i\th$ row of $\mathsf{DFT}_{m/2}$ evaluates the polynomial at $\omega_{m/2}^i$,\footnote{In this intuition, we use the standard order and ignore bit reversal for simplicity.} and hence contains sequential powers of $\omega_{m/2}^i$. The $j\th$ entry of $\hat{T}_m$ is $\omega_m^j$, so
\[\omega_{m/2}^{i\cdot j}\cdot \omega_m^j = \omega_{m}^{2i\cdot j}\cdot \omega_m^j = \omega_m^{(2i+1)\cdot j}.\]
Thus the twiddle matrix transforms $\mathsf{DFT}_m/2$ to evaluate the polynomial at odd powers of $\omega_m$, i.e., $\omega_m^i$ for $i\in\Z_m^*$.

An alternate way to view this process is that the DFT does a \emph{cyclic convolution} to (in the $p=2$ case) map from $\Z_q[X]/(X^N-1)$ to $Z_q^{N}$. We need a \emph{negacyclic convolution} to map from (in the $p=2$ case) $\Z_q[X]/(X^N+1)$ to $Z_q^{N}$. We call the linear operator that achieves the negacyclic convolution the \emph{number theoretic transform} (NTT).
See~\cite{cryptoeprint:2024/585} for a good introduction to these concepts.

Formally, for a generic cyclotomic index $m=p^e$, $\mathsf{NTT}_m$ is the $\frac{m}{2}\times\frac{m}{2}$ (i.e., $N\times N$) transformation whose decomposition is
\[\mathsf{NTT}_m = \parens*{I_{p-1}\otimes \mathsf{DFT}_{m/2}}\cdot \hat{T}_m\cdot (\mathsf{NTT}_p\otimes I_{m/2}),\]
where 
When $p=2$, $\mathsf{NTT}_2 = [1]$, so this simplifies to 
\[\mathsf{NTT}_m = \mathsf{DFT}_{m/2}\cdot \hat{T}_m,\]
as noted above.

Similarly,
\[\mathsf{NTT}^{-1}_m = (\mathsf{NTT}^{-1}_p\otimes I_{m/2})\cdot \hat{T}^{-1}_m\cdot \parens*{I_{p-1}\otimes \mathsf{DFT}^{-1}_{m/2}},\]
or
\[\mathsf{NTT}_m^{-1} = \hat{T}_m^{-1}\cdot \mathsf{DFT}_{m/2}^{-1}\]
when $p=2$.

This can be combined with any DFT decomposition, with the caveat that bit-reversal still applies.
There are a few subtleties here worth noting: $\hat{T}_m$ uses $m\th$ roots of unity, even though the transform is $\frac{m}{2}\times\frac{m}{2}$. In the recursive calls, (e.g., to $\mathsf{DFT}_{m/2}$ we need to use an $(m/2)\th$ root of unity, which we can obtain by computing $\omega_{m/2}=\omega_m^2$, or by using a ``stride'' of two when accessing an array that contains increasing powers of $\omega_m$. 

We also note that in many cases, bit reversal (to get the output of DFT/NTT in standard order) is \emph{not} required. The same is not true for the CKKS encoding step, which uses a similar decomposition.

To summarize, when using a ring dimension of $N$, we apply $\mathsf{NTT}_{2N}$ to both inputs, multiply them component-wise, and then apply $\mathsf{NTT}^{-1}_{2N}$.

\subsection{Multiplication in $\Z[i][X]/(X^n-i)$}
Next we consider $\mathcal{O}(n\log{n})$ multiplication in the Gaussian ring $\Z[i][X]/(X^n-i)$, where $n=m/4$. In this case, the eigenvectors are $[\omega_m^{(4i+1)n}, \omega_m^{(4i+1)(n-1)}, \ldots, \omega_m^{4i+1},1]$ for $k\in[0,m/4)$. AI decided to define $F$ as having eigenvector columns. Then $F^{-1} = D_\mathrm{scale}\cdot NTT$, where $D_\mathrm{scale}$ is a diagonal matrix. Note that since $F^{-1}$ corresponds to the forward transformation, we can skip multiplication by $D_\mathrm{scale}$ and use $F'^{-1}=NTT$ as the forward transformation. The catch is that we need to use an $m\th$ root of unity in $\zeta_m\in \Z_q[i]$ rather than the $\omega_m\in\Z_q$ that we use for the integer ring. We require $\zeta_m^{m/4} = i$. We can compute $\zeta_m$ from $\omega_m$ as $x_1 = \omega_m$ and $x_2 = \omega_m^3$. Note that $x_2^n = \omega_m^{3n} = \omega_m\cdot \omega_m^{2n} = \omega_m\cdot \omega_m^{m/2} = -\omega_m^n$. Then $\zeta_m = (2^{-1}(x_1+x_2)) + ((2\omega_m^n)^{-1}(x_1-x_2))i$.

\section{Encoding}
\label{sec:ckksencoding}
    In CKKS, a plaintext is a vector $v\in \C^{N/2}$, where $N$ is the ring dimension. CKKS encrypts each coefficient of $v$ into a \emph{slot}. These slots enable batching, which helps improve the efficiency of homomorphic encryption. Each ciphertext operation induces the same operation on each slot independently.	
	
    During encryption, we apply a transformation $\tau^{-1}: \C^{N/2}\rightarrow \R[X]/(X^N+1)$, and then round the coefficients to get a polynomial $m(X)\in R=\Z[X]/(X^N+1)$ with integer coefficients. This process is called ``encoding''. We then encrypt this polynomial to the ciphertext $(-a(X)\cdot s(X) + m(X) + e(X), a(X))\in R_Q^2$ for an error polynomial $e(X)$, random polynomial $a(X)$, and secret polynomial $s(X)$.
	
    For an arbitrary ciphertext, 
    \[\inner{ct, sk} = t(X) = m(X)+q\cdot I(x)\in R,\]
    where $m(X)$ is the encoding of a message\footnote{Message has $N/2$ complex components; its encoding has $N$ coefficients} and $q$ is small\footnote{Or equivalently, the ciphertext has few RNS components.}. CKKS maintains $I(x)$ to have small coefficients; this doesn't matter for decryption, but it's critical for bootstrapping.\footnote{\label{footnote:sparsekey}\cite{cryptoeprint:2018/153} shows that $\length{I}_\infty = \mathcal{O}\parens*{\sqrt{h}}$, where $h$ is the Hamming weight of the (binary) secret key.} The actual decryption formula is therefore $\bracks{\inner{ct, sk}}_q = m(X)\in R_q$, where $m(X)$ implicitly includes an error term. We recover the (noisy) plaintext slots by decoding $m(X)$ to $\tau(m(X))$.
	
    The decoding function $\tau$ maps a polynomial in $\R[X]/(X^N+1)$ to the values held in the slots in $\C^{N/2}$\footnote{We apply $\tau$ to polynomials in $R=\Z[X]/(X^N+1)\subset \R[X]/(X^N+1)$.}. For a polynomial $m(X)$, we can recover the slots via the following $\frac{N}{2}\times N$ linear transform~\cite{cryptoeprint:2018/153}:
    \[U=
	\begin{bmatrix}
		1 & \zeta_0 & \zeta_0^2 & \ldots & \zeta_0^{N-1} \\
		1 & \zeta_1 & \zeta_1^2 & \ldots & \zeta_1^{N-1} \\
		\vdots & \vdots & \vdots & \ddots & \vdots \\
		1 & \zeta_{\frac{N}{2}-1} & \zeta_{\frac{N}{2}-1}^2 & \ldots & \zeta_{\frac{N}{2}-1}^{N-1} \\
		
	\end{bmatrix}
    \]
	
    The encoding function $\tau^{-1}$ can be achieved\footnote{The actual encoding function is $\round*{\frac{\Delta}{N}\parens*{\overline{U}^\intercal\cdot z+U^\intercal \cdot \overline{z}}}$. We can ignore the scaling by $\Delta$ and rounding for bootstrapping.} as
    \[m(X) = \frac{1}{N}\parens*{\overline{U}^\intercal\cdot z+U^\intercal \cdot \overline{z}}\]

    \subsection{Decomposition}
    \label{sec:sfdecomp}

    First, it defines a ``special Fourier transform'' matrix $\mathsf{SF}_n$ which evaluates the polynomial at $\omega_m^{5^k}$ for $k\in[0, n)$. Note that this is the same set as $\omega_m^{1+4k}$, but in a different order. \cite{cryptoeprint:2018/1043} gives a dense matrix description, but it doesn't make much sense to me. However, we can view $\mathsf{SF}$ as an NTT over $\C$. As a result, we can write

    where $\Pi$ is a permutation matrix that maps the NTT output order (either bit-reversed or natural, if applying bit-reversal) to the order $\omega^{5^j \bmod 2N}$, which is preferable for rotations.

    Similarly the the encoding function can be described as

    \end{align}

\section{A Word on DIF, DIT, and BitReversal}
At this point, we have seen that NTT and decoding are essentially the same, over different fields. Either can be expressed using a ``decimation-in-time'' (DIT) or ``decimation-in-frequency'' (DIF) style. With DIF, in the forward direction, the input is in natural order and the output is in bit-reversed order. Put another way, it evaluates a polynomial with natural-order coefficients at roots of unity, but the evaluation points are in bit-reversed order. By contrast, with DIT in the forward direction, the input is in bit-reversed order and the output is in natural order. Therefore, DIT takes polynomial coefficients in bit-reversed order and evaluates the polynomial at target roots of unity in natural order.

Generally, the choice for NTT doesn't much matter, but there are several options that an implementation could choose for encoding, and these turn out to have a major impact:
\begin{itemize}
	\item DIF encoding with bit-reversal
	\item DIF encoding without bit-reversal
	\item DIT encoding with bit-reversal
	\item DIF encoding without bit-reversal
\end{itemize}
First note that ``DIF with bit-reversal'' and ``DIT with bit-reversal'' are identical, because these algorithms implement the exact same linear transform with the same input and output orderings. So really there are only three options to consider. The choice of the NTT implementation depends on the encoder choice.

Let's consider the case of using bit-reversal. In this case, the slots are encoded in the order that the application expects, and the polynomial representation is with respect to the standard polynomial basis order. Operations that depend on the basis order, such as $\mathsf{MulByX}$, $\mathsf{Embed}$, Gaussian/Integer isomorphism, $\mathsf{CoeffsToCosets}$, and automorphisms are therefore implemented in the standard basis order. With this choice, we can implement NTT using DIF with or without final bit-reversal, because it doesn't matter which order the NTT evaluations are in. Alternately, we could use DIT with bit-reversal for the NTT.

Now suppose we use DIF \emph{without} bit-reversal. This means that the polynomial coefficients are in standard order (so no change to the operations listed above), but the slots are permuted. This means that operations like rotations are much harder, if not impossible. This could ultimately bleed into the application layer, which would be disastrous. With this choice, we can implement NTT using DIF with or without final bit-reversal, because it doesn't matter which order the NTT evaluations are in. Alternately, we could use DIT with bit-reversal for the NTT.

On the other hand, if we implement DIT without bit-reversal, the slots are in the order that the application expects, but the polynomial coefficients are permuted. This makes operations that depend on the polynomial basis ordering more complex. With this choice, we would implement NTT using DIT without bit-reversal, since it is the only choice that handles polynomial coefficients in bit-reversed order.

Why, then, would an implementation choose to \emph{not} use bit-reversal in encoding? Unfortunately, there's a very good reason: bootstrapping. Recall that bootstrapping involves homomorphic encoding and decoding. It turns out that there is an alternate factorization of bit-reversed $\mathsf{SF}$ that yields a more symmetric decomposition than the one given above. This is the factorization used in the ``slots-to-coeffs'' (decoding) and ``coeffs-to-slots'' (encoding) steps of bootstrapping.\footnote{Typically, we have a ciphertext that encrypts slots. If we want to move the slots to the coefficients of the plaintext, we need to apply a linear transform on the coefficients that yields the slots. That's exactly what the \emph{decoding} function does, hence $\mathrm{S2C}$ is just homomorphic decoding.} If we use a DIT encoding without bit-reversal, this corresponds to a nice factorization for the homomorphic transforms. If instead we apply bit-reversal in encoding, we have to \emph{undo} the bit-reversal prior to applying the nice factorization. Applying bit-reversal is apparently a very costly operation homomorphically, hence it may be preferred to use the DIT encoding sans bit-reversal.

There is one more option, however. Suppose we implement encoding with bit-reversal, so that the application layer and the polynomial layer are sane. In bootstrapping, we will use a decimation-in-frequency decomposition for encoding/decoding that does \emph{not} include bit reversal. This enables an efficient implementation. Since bootstrapping rounds slot-wise, the order of the slots doesn't matter. The inverse transform expects bit-reversed slots, which brings back a standard polynomial ordering after bootstrapping. See~\cref{ch:bootstrapping} for more details.

\section{Multiplication}
    \cite{cryptoeprint:2023/1788} shows how to reduce the modulus consumption of multiplication by decomposing ciphertexts into smaller components, akin to large-word multiplication: if $x_0,x_1$ are both $2k$ bits, we can write them as $x_i = 2^kx_{i,1} + x_{i,0}$. It's also a bit like composite scaling, since performance degrades quadratically in the size of the decomposition.
    
    The authors argue that using a decomposition of size two (i.e., as in the example above) halves modulus consumption, and thereby enables an application to use half the ring dimension (while maintaining the same number of levels as the original ring dimension with regular multiplication).
    
    The implementation seems very complex, and it may be subsumed by other options.

\section{Automorphisms}
\label{sec:automorphisms}
One simple operation is to apply a ring automorphism to a ciphertext. The automorphism $\sigma_k$ maps $X$ to $X^k$ for some $k\in \Z_m^*$ for cyclotomic index $m$. For a ciphertext $\parens*{a, b}$ encrypting a message $t$, the ciphertext $\parens*{\sigma_k(a), \sigma_k(b)}$ decrypts to $\sigma_k(t)$ under the key $\sigma_k(s)$. We consider different rings below.

\subsection{Power-of-two Integer Rings}
We consider the cases where the input is in coefficient form and NTT form.

In coefficient form, we simply apply the variable substitution and reduce. Specifically, the coefficients of the output are
\[c_{j\cdot k\bmod N} = 
\begin{cases}
	c_j  & \text{if $j\cdot k\bmod m < N$}\\
	-c_j & \text{otherwise}
\end{cases}\] 
This is because in the former case, we would replace $X^N$ by $-1$ an even number times, while in the latter case, we replace it an odd number of times.

We can also apply the automorphism in the NTT basis. In the evaluation basis, $\sigma_k$ maps evaluation at $\omega^j$ to $\omega^{j\cdot k}$ for $j\in\Z_m^*$ in the order $1, 3, 5, \ldots$.\footnote{Note that bit-reversal may apply depending on your NTT.} Assuming for now that the NTT is not bit-reversed, we can apply the automorphism in the NTT basis as follows:
\[c_{\mathrm{BR}\parens*{\frac{(j\cdot k \bmod m) - 1}{2}}} = 
 	c_{\mathrm{BR}\parens*{\frac{j - 1}{2}}}.\]
This is slightly simpler than applying $\sigma_k$ in the coefficient basis because there is only one case to consider, and we don't need to track a constant.

\subsection{Gaussian Ring}
We only consider coefficient form for the Gaussian ring; the NTT form is more complex. First, we need some algebra background. Like the integer ring, the Gaussian ring is a $\Z$-algebra, meaning it embeds $\Z$. Any automorphism fixes $\Z$ pointwise (because the definition of a homomorphism fixes $1$). As a result, we must consider how the automorphism acts not only on the polynomial indeterminant, but also on $i$. Since $i^4=i$, we only need to consider $k\bmod 4$. We're also assuming that $k\in\Z_m^*$, so we only need to consider the cases of $k\equiv 1\bmod 4$ (which isn't very exciting) and $k\equiv 3\bmod 4$. In the latter case, $i\mapsto i^3=-i$. This means that before applying the automorphism to the indeterminant, we conjugate each coefficient.

After possibly conjugating each coefficient, we then apply the automorphism to the indeterminant. In coefficient form, we simply apply the variable substitution and reduce. Specifically, the coefficients of the output are
\[c_{j\cdot k\bmod n} = 
\begin{cases}
	c_j  & \text{if $j\cdot k\bmod m < n$}\\
	i\cdot c_j  & \text{if $n\le j\cdot k\bmod m < 2n$}\\
	-c_j  & \text{if $2n\le j\cdot k\bmod m < 3n$}\\
	-i\cdot c_j & \text{otherwise}
\end{cases}\] 

\subsection{Prime Ring}
We only consider coefficient form for prime rings for now. An important identity is that $\Phi_p(X)\cdot (X-1) = X^p-1$. Since $\Phi_p(X)=0$ in $\Z[X]/(\Phi_p(X))$, $X^p-1=0\Rightarrow X^p=1$ in this ring. This means that we only need to consider the index mod $p$.

Start by initializing all of the new coefficients to 0. If $j\cdot k\equiv p-1 \bmod p$, subtract $c_j$ from all of the new coefficients. Otherwise, set $c_{j\cdot k \bmod p} = c_j$.

\subsection{Hoisting}
If we need to apply multiple automorphisms to the same ciphertext, we can apply (double-) hoisting. For this technique, we split key-switching into two steps:
\begin{enumerate}
	\item Decomposition + Basis Extension
	\item DotProduct + ModDown
\end{enumerate}

The basic way to use automorphisms is to apply the automorphism to get an encryption of $\sigma_i(m)$ under $\sigma_i(s)$, and the apply a key-switch from $\sigma_i(s)$ back to $s$. With hoisting, we will instead apply (hoisted) key-switches from $s$ to $\sigma_i^{-1}(s)$ to get an encryption of $m(X)$ under $\sigma_i^{-1}(s)$, then apply $\sigma_i$ to get an encryption of $\sigma_i(m)(X)$ under $\sigma_i(\sigma_i^{-1}(s)) = s$. Note that $\sigma_i^{-1}=\sigma_{i^{-1} \bmod 2N}$.

The full process then is:
\begin{enumerate}
	\item Decompose and extend the basis of the $a$-part of the input ciphertext.
	\item Compute the dot product of the extended $a$-part with each of the (inverse) key-switch keys, then ModDown each.
	\item Add the original input ciphertext to complete the keyswitch.
	\item Apply the corresponding automorphism to each output ciphertext.
\end{enumerate}

\section{Conjugation}
Since $\sigma_k$ maps a slot evaluated at $\omega^j$ to the slot evaluated at $\omega^{j\cdot k}$ and evaluation at $\omega^{-j}$ is the conjugate of evaluation at $\omega^j$, conjugation corresponds to $\sigma_{-1}=\sigma_{m-1}$.
